# 릴리스 점검

## 점검 절차

PRD.md·README.md, 진입 HTML, 모듈 경로, 빌드 설정과 존재하는 배포 workflow를 읽는다. 문서화된 실행·테스트·빌드 명령을 실행하고 정적 결과를 확인한다. GitHub Pages 설정은 접근 가능한 저장소 정보나 제공된 설정 근거로 읽기 전용 확인한다. 확인할 수 없는 원격 설정을 추정하지 않는다.

코드·문서·저장소 설정을 직접 수정하지 않고 commit·push·배포를 수행하지 않는다. 없거나 실행할 수 없는 검사와 원격 설정은 미검증 및 릴리스 차단 여부로 명시한다. 이 skill 자체는 배포 승인을 대신하지 않는다.

## 점검 체크리스트

- [ ] 파일 연결: HTML의 script·stylesheet 및 모듈·이미지 경로를 확인한다.
  - 통과: 모든 참조 파일이 배포 결과에 존재하고 대소문자까지 일치한다 / 실패: 누락 파일·잘못된 상대 경로·대소문자 차이가 있다.
- [ ] 정적 실행: 실제 배포 대상 폴더를 정적 서버로 연다.
  - 통과: 초기화·조작이 가능하고 파일 404·모듈 로딩·콘솔 오류가 없다 / 실패: 개발 서버에서만 동작하거나 배포 결과에서 오류가 난다.
- [ ] 프로젝트 하위 경로: Pages 주소 형태에 맞춰 경로를 확인한다.
  - 통과: 프로젝트 사이트의 저장소 하위 경로 또는 사용자 사이트 루트에서 리소스가 정상 로딩된다 / 실패: 루트 절대 경로 등으로 실제 사이트 경로에서 리소스가 깨진다.
- [ ] 실행 문서: README의 필수 도구·실행·테스트·빌드 절차를 따른다.
  - 통과: 기록된 명령이 현재 프로젝트와 일치하고 필요한 배포 폴더를 만들 수 있다 / 실패: 명령·의존성·출력 폴더가 누락되거나 문서와 다르다.
- [ ] 배포 방식과 설정: 선택한 Pages 방식의 설정을 확인한다.
  - 통과: 브랜치 배포는 브랜치·폴더에 진입 파일이 있고 Actions 배포는 workflow·아티팩트·배포 작업·필요 권한이 연결된다 / 실패: 선택한 방식의 소스·결과물·권한이 맞지 않아 배포할 수 없다.
- [ ] 원격 상태: 읽기 가능한 Pages 설정과 기존 배포 결과를 확인한다.
  - 통과: 실제 설정이 로컬 계획과 일치하고 기존 배포가 있다면 그 결과와 주소를 확인했다 / 실패: 설정 불일치나 확인된 배포 실패가 있다.
- [ ] 릴리스 기능: 기존 테스트와 시작·줄 제거·Game Over·Restart를 확인한다.
  - 통과: 테스트가 통과하고 배포 대상에서 해당 흐름이 정상 동작한다 / 실패: 테스트 실패 또는 배포 대상에서 기능 회귀가 있다.
- [ ] MVP 의존성: 런타임 요구사항과 범위를 확인한다.
  - 통과: 플레이에 설치·로그인·유료 외부 서비스가 필요하지 않는다 / 실패: PRD에 없는 필수 계정·유료 서비스·클라이언트 설치가 필요하다.

## 보고

검사별 통과·실패·미검증, 실행 명령·결과, 확인한 설정 근거를 적는다. 배포 준비 상태를 준비 완료·차단·추가 확인 필요 중 하나로 요약한다. 원격 권한 또는 실제 배포 확인이 없으면 로컬 검증 완료와 구분한다. 높음은 배포·실행 불가나 핵심 회귀, 중간은 경로·설정·문서 불일치, 낮음은 기능을 막지 않는 문서 부족이다. 문제없으면 발견된 문제 없음을 명시한다.

| 항목 | 심각도(높음·중간·낮음) | 개선안 |
|---|---|---|
| 파일:줄 또는 설정과 릴리스 차단·미검증 근거 | 높음·중간·낮음 중 하나 | 경로·문서·설정 개선 방향 및 필요한 확인 |
