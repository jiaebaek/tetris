# UI 코드 리뷰

## 점검 절차

PRD.md와 README.md의 UI·조작 규칙을 확인하고 HTML, 스타일, 렌더링 및 이벤트 연결 코드를 읽는다. 관련 테스트와 가능한 브라우저 확인을 수행한다. 코드 스타일 선호를 기능 결함과 구분한다. 코드를 직접 수정하지 않으며 실행하지 못한 검사는 미검증으로 보고한다.

## 점검 체크리스트

- [ ] DOM 구조: 보드·점수·종료 안내·Restart 요소와 선택자를 확인한다.
  - 통과: 현재 단계의 필수 요소가 있고 ID가 중복되지 않으며 선택자가 올바른 요소를 찾는다 / 실패: 요소 누락·중복 ID·잘못된 선택자로 표시나 조작이 깨진다.
- [ ] 조작 요소: 버튼과 키보드 안내를 확인한다.
  - 통과: Restart는 키보드로도 사용할 수 있는 버튼이며 안내가 실제 키 매핑과 일치한다 / 실패: 버튼을 키보드로 사용할 수 없거나 안내와 동작이 다르다.
- [ ] 상태 렌더링: 빈 칸·현재 블록·고정 블록의 좌표를 확인한다.
  - 통과: 10 × 20 보드와 상태를 정확히 표시하고 이전 프레임 잔상이 없다 / 실패: 좌표가 어긋나거나 이동·라인 제거 후 잘못된 칸이 남는다.
- [ ] 렌더링 부작용: 같은 상태로 연속 렌더링한다.
  - 통과: 화면 결과가 같고 보드·점수·블록 상태를 바꾸지 않는다 / 실패: 렌더링 횟수에 따라 상태가 변하거나 요소가 누적된다.
- [ ] 이벤트 수명: 초기화·렌더링·Restart의 리스너 등록 경로를 확인한다.
  - 통과: 한 입력이 한 번 처리되고 필요한 해제가 이루어진다 / 실패: 반복 렌더링이나 Restart 후 입력이 중복 처리된다.
- [ ] 가독성: 함수 책임·명명·반복 코드·상수를 확인한다.
  - 통과: 함수 목적이 명확하고 같은 규칙이 한 곳에서 관리된다 / 실패: 모호한 이름이나 중복 규칙 때문에 변경 위치와 동작을 추적하기 어렵다.

## 보고

검사별 판정과 파일·줄, 재현 절차 또는 테스트 결과를 기록한다. 높음은 화면·입력 불능이나 상태 손상, 중간은 잘못된 표시·이벤트 처리, 낮음은 명명·가독성 문제다. 미검증은 이유와 필요한 확인을 적는다. 문제없으면 발견된 문제 없음을 명시한다.
