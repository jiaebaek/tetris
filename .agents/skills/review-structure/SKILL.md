# 구조 점검

## 점검 절차

PRD.md, README.md, 적용되는 AGENTS.md를 읽고 현재 구현 단계의 파일과 실행 명령을 확인한다. 게임 로직, 렌더링, 입력·시간 처리의 의존 관계를 추적한다. 문서에 있는 실행·테스트 명령을 실행하고 결과를 기록한다. 향후 작업으로 명시된 미구현 기능은 현재 단계의 실패로 취급하지 않는다.

코드를 직접 수정하지 않는다. 실행할 수 없는 검사는 미검증으로 표시하고 이유를 적으며 통과로 간주하지 않는다.

## 점검 체크리스트

- [ ] 파일 구조: 진입점과 소스·테스트의 위치를 확인한다.
  - 통과: 각 파일의 역할과 진입 경로가 명확하다 / 실패: 진입점이 없거나 중복 파일로 실행 대상을 구분할 수 없다.
- [ ] 게임 로직 분리: 상태·충돌·회전·점수 코드의 의존성을 확인한다.
  - 통과: DOM과 실제 타이머 없이 핵심 로직을 테스트할 수 있다 / 실패: 로직 실행에 브라우저 화면이나 실제 시간 경과가 필수다.
- [ ] UI와 입력·시간 처리 분리: 렌더링과 상태 변경의 책임을 확인한다.
  - 통과: 렌더러는 상태를 표시하고 입력·루프는 정해진 로직 함수를 호출한다 / 실패: 렌더링이 점수·보드를 변경하거나 게임 규칙이 여러 계층에 중복된다.
- [ ] 모듈 연결: import·export와 초기화 순서를 확인한다.
  - 통과: 참조가 유효하고 순환 의존으로 초기화가 깨지지 않는다 / 실패: 누락된 참조나 순환 초기화로 실행 오류가 발생한다.
- [ ] 실행 가능성: README의 로컬 실행 절차를 확인한다.
  - 통과: 문서화된 명령으로 페이지가 열리고 리소스 로딩·초기화 오류가 없다 / 실패: 누락된 명령·의존성·파일 때문에 실행하지 못한다.
- [ ] 테스트 진입점: 테스트 실행 및 난수·시간 제어 방식을 확인한다.
  - 통과: 현재 단계의 테스트를 실행할 수 있고 필요한 난수·시간을 제어할 수 있다 / 실패: 테스트 명령이 없거나 같은 입력을 재현할 수 없다.

## 보고

검사별 통과·실패·미검증과 근거를 먼저 요약한다. 문제는 높은 심각도부터 아래 표로 보고한다. 높음은 실행 불가·상태 손상, 중간은 테스트·유지보수를 방해하는 결합, 낮음은 이해를 방해하는 구조·명명 문제다. 문제없으면 표 대신 발견된 문제 없음을 명시한다.

| 항목 | 심각도(높음·중간·낮음) | 개선안 |
|---|---|---|
| 파일:줄 또는 모듈과 문제 근거 | 높음·중간·낮음 중 하나 | 책임 분리 또는 연결 수정 방법과 확인할 테스트 |
