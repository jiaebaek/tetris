# 안전한 리팩터링

## 수행 절차

이 skill은 예외적으로 코드를 직접 리팩터링한다. PRD.md·README.md·적용되는 AGENTS.md와 기존 변경을 읽고 개선 대상 및 기능·공개 API의 보존 범위를 적는다. 공개 API에는 export 이름, 호출 인자·반환값, 외부에서 관찰하는 동작과 사용 중인 DOM 연결 계약을 포함한다.

1. 기존 테스트 명령을 실행해 변경 전 기준 결과를 확보한다. 누락된 핵심 동작은 필요한 회귀 테스트를 먼저 추가하고 원본 구현에서 통과를 확인한다.
2. 테스트가 실패하거나 실행 불가라면 기준 결과와 문제를 보고하고 코드 리팩터링에 착수하지 않는다. 기준 실패를 고치는 기능 수정은 별도 작업으로 보고한다.
3. 중복 제거·함수 추출·모듈 책임 정리 중 요청에 필요한 작은 변경을 수행한다. 사용자의 기존 변경을 보존하고 규칙·점수·속도·조작키·공개 API를 바꾸지 않는다.
4. 작은 변경마다 관련 테스트를 실행하고 마지막에 변경 전과 동일한 전체 테스트 명령 및 영향받는 화면 흐름을 확인한다.
5. 실패하면 이번 리팩터링 부분을 수정하거나 해당 부분만 되돌린다. 사용자 변경을 덮어쓰는 전체 초기화는 하지 않는다. 테스트를 삭제·완화해 성공으로 만들지 않는다.
6. diff를 검토하고 변경 전후 테스트 명령·통과 수·실패 수·실행 결과와 실제 변경 내용을 보고한다. 실행하지 않은 검증은 미검증으로 표시한다.

## 점검 체크리스트

- [ ] 변경 전 기준: 동일한 테스트 환경과 입력에서 원본 결과를 확보한다.
  - 통과: 관련 회귀 테스트와 기존 전체 테스트가 모두 통과한다 / 실패: 실패가 있거나 실행하지 못했으며 리팩터링을 시작할 기준이 없다.
- [ ] 기능 보존: 이동·회전·고정·줄 제거·점수·종료·Restart를 비교한다.
  - 통과: 동일한 상태·입력·난수·시간에서 변경 전후 결과가 같다 / 실패: 규칙이나 사용자에게 보이는 동작이 달라진다.
- [ ] 공개 API 보존: export 및 호출 계약과 DOM 연결을 비교한다.
  - 통과: 기존 호출부를 바꾸지 않아도 이름·인자·반환값·계약이 유지된다 / 실패: 외부 호출부 변경이나 동작 계약 변경이 필요하다.
- [ ] 구조 개선: 추출·분리·중복 제거의 효과를 확인한다.
  - 통과: 구체적 중복 또는 결합이 줄고 책임이 명확해진다 / 실패: 근거 없는 계층·추상화가 늘거나 요청과 무관한 변경이 섞인다.
- [ ] 상태·이벤트 보존: 타이머·리스너·상태 참조 수명을 확인한다.
  - 통과: Restart 및 종료에서 기존 정리 동작이 유지되고 중복 실행이 없다 / 실패: 상태 공유·리스너 누적·루프 중복이 생긴다.
- [ ] 변경 후 테스트: 기준과 동일한 전체 테스트 및 필요한 화면 검증을 실행한다.
  - 통과: 변경 전후 모두 통과하고 테스트 삭제·완화 없이 회귀가 없다 / 실패: 후속 실패·미실행 또는 검증 약화가 있다.
- [ ] 변경 범위: 최종 diff와 기존 사용자 변경을 확인한다.
  - 통과: 리팩터링 범위만 바뀌고 기존 사용자 변경은 보존된다 / 실패: 기능 수정·무관한 변경·사용자 변경 손실이 포함된다.

## 보고

수행한 구조 개선과 API·기능 보존 근거를 적고 변경 전후 테스트 결과를 나란히 보여준다. 남은 문제나 착수 차단 사유는 아래 표로 보고한다. 높음은 회귀·API 변경·사용자 변경 손실, 중간은 테스트 공백·불필요한 결합, 낮음은 명명·정리 문제다. 문제없으면 발견된 문제 없음을 명시한다. 모두 통과하기 전에는 완료로 보고하지 않는다.

| 항목 | 심각도(높음·중간·낮음) | 개선안 |
|---|---|---|
| 변경 위치와 남은 문제 또는 차단 근거 | 높음·중간·낮음 중 하나 | 필요한 수정·복구 또는 추가 검증 |
